# Change Log — 2026-05-04 18:23

## Summary

Two targeted regression fixes applied as part of emergency audit (7 real-device regressions). No new features, no redesigns. `flutter analyze` passes with zero issues.

**Fix 1 — Prayer notifications default OFF**
`UserSettings.isPrayerEnabled` was `true`, causing `PrayerNotificationScheduler` to fire on every fresh install before the user had enabled prayer features in Settings.

**Fix 2 — iOS widget App Group race condition**
`WidgetDataService.init()` (which calls `HomeWidget.setAppGroupId()`) was called inside `_initBackground()`, which runs after `runApp()`. Global cubits push widget data on first state emission, which can happen before the App Group is configured, landing data in the default UserDefaults suite instead of `group.com.iappsnet.athar`. Moved `init()` call to before `runApp()`.

---

## Files Modified

### 1. `lib/features/settings/data/models/user_settings.dart`

**What changed:** Two lines — field declaration default and constructor parameter default.

```diff
-  bool isPrayerEnabled = true; // السويتش الرئيسي
+  bool isPrayerEnabled = false; // السويتش الرئيسي — OFF by default, user must enable in Settings

-    this.isPrayerEnabled = true, // تأكد من إضافته للبناء
+    this.isPrayerEnabled = false, // OFF by default
```

**Note:** The diff also shows `lastSyncAt`/`lastSyncError` fields and SYNC section header — those are pre-existing working-tree changes not made in this session.

**Before:** Any fresh install or cleared-data install would auto-schedule prayer notifications because `isPrayerEnabled` defaulted to `true`. `PrayerNotificationScheduler.initializeScheduling()` exits early only when `false`.

**After:** Fresh installs default to `false`. User must explicitly enable prayer in Settings. Existing Isar records with `isPrayerEnabled = true` (users who already had it enabled) are unaffected — Isar reads the stored value, not the field default.

---

### 2. `lib/main.dart`

**What changed:** `WidgetDataService.init()` moved from `_initBackground()` to before `runApp()`. Plus pre-existing working-tree changes visible in diff (import `sync_service.dart` → `sync_cubit.dart`, `SyncService.syncTasks()` → `SyncCubit.triggerSync()`, added `initializeDateFormatting('en_US', null)`) — those were **not made in this session**.

**Changes made in this session only:**

```diff
 // in main() — ADDED before runApp():
+  // ── Widget App Group must be set BEFORE runApp so the global cubits'
+  // first widget-data push lands in the correct UserDefaults suite.
+  await getIt<WidgetDataService>().init();

 // in _initBackground() — REMOVED:
-  await getIt<WidgetDataService>().init();
+  // WidgetDataService.init() is called before runApp() — do not repeat here.
```

**Before:** `HomeWidget.setAppGroupId("group.com.iappsnet.athar")` was called after `runApp()`. Global cubits (HabitCubit, TaskCubit, PrayerCubit) emit their first state during `MultiBlocProvider` initialization inside `runApp()`, which triggers `WidgetDataService.pushHabitData()` / `pushTaskData()` / `pushPrayerData()`. Those calls write to `UserDefaults` using `HomeWidget.saveWidgetData()`, which uses whatever App Group is configured at call time — none, at that point.

**After:** App Group is set synchronously before `runApp()`. All widget data writes land in the correct `group.com.iappsnet.athar` UserDefaults suite regardless of timing.

## Follow-up (Remaining Open Issues)

These issues were identified during the audit but **not fixed in this session**:

1. **Widget skeleton (ISO parse / working-tree Swift files)** — `AtharPrayerWidget.swift`, `AtharHabitWidget.swift`, `AtharTaskWidget.swift` in the working tree already contain the fixes (epoch timestamp + multi-format ISO fallback, `AppIntentTimelineProvider`, `WidgetLanguage` enum). These need to be committed and the app rebuilt + installed on device to take effect.

2. **NavBar + button cannot save Task/Habit** — code-traced as correct; suspected cause is prayer conflict dialog UX confusion (dialog appears, user does not see "Force Save" option) or HabitFormSheet silent-close on empty title. Needs device testing to confirm actual root cause.

3. **HabitFormSheet UX gap** — `_saveHabit()` calls `Navigator.pop(context)` outside the `if (titleController.text.isNotEmpty)` block → sheet closes silently on empty title with no error shown. Decision pending from user whether to fix.

4. **Athkar in Habit widget** — `HabitType.athkar` habits use `athkarItems` array for completion (incompatible with widget's simple toggle intent). Three options: (a) show read-only count, (b) add `IncrementAthkarIntent` with atomic counter, (c) keep athkar excluded. Decision pending.

5. **Widget locale (Phase 5 P1)** — `LocaleCubit.setLocale()` does not write to `athar_app_locale` in UserDefaults. Widgets do not follow in-app language changes. Documented in `docs/ai/KNOWN_PROBLEMS.md`.
