# Change Log — Phase 8 — Separate Prayer Dashboard Visibility from Prayer Notifications
# 2026-05-06

---

## 1. Root Cause

`isPrayerEnabled` was used ambiguously for two unrelated concerns:

| Concern | Correct flag | Was using |
|---------|-------------|-----------|
| Prayer card/dashboard visibility | `isPrayerEnabled` | `isPrayerEnabled` ✅ |
| Prayer notification scheduling gate | `isPrayerNotificationsEnabled` (new) | `isPrayerEnabled` ❌ |

This meant: enabling the prayer dashboard card also scheduled notifications; disabling the card cancelled notifications. A user who wanted only dashboard visibility (no athan alerts) or only athan alerts (no dashboard card) had no way to achieve either independently.

Two additional open bugs from Phase 7 were fixed here:
- `handleAutoRenewal()` had no `isPrayerNotificationsEnabled` guard — auto-renewal could schedule notifications after the user disabled them (race condition).
- `settings?.isPrayerEnabled ?? true` in the UI caused the prayer card toggle to flash ON during the null-settings load state.

## 3. Settings Model Decision

```dart
// user_settings.dart

/// Controls prayer card / dashboard feature visibility only. Does NOT schedule notifications.
bool isPrayerEnabled = false;               // default: card hidden (user opt-in)

/// Controls prayer athan notification scheduling. Independent of card visibility.
bool isPrayerNotificationsEnabled = false;  // default: OFF — user must explicitly opt in

/// 15-min early reminder. Sub-setting under isPrayerNotificationsEnabled.
bool enablePrayerReminders = true;          // default: ON when notifications enabled
```

**Existing users (Isar migration):** Isar uses Dart field defaults for missing fields on existing records. `isPrayerNotificationsEnabled` will read as `false` until the user saves settings. This is safe — no notifications are scheduled without explicit opt-in.

**No existing `isPrayerEnabled = true` users lose notifications silently** — they still have the card visible; only the new notification field matters for scheduling.

## 4. Scheduling Fix

### `initializeScheduling()` guard
```swift
// BEFORE:
if (!(settings.isPrayerEnabled)) { await disableNotifications(); return; }

// AFTER:
if (!settings.isPrayerNotificationsEnabled) { await disableNotifications(); return; }
```

### `handleAutoRenewal()` — new guard (fixes Phase 7 open bug)
```dart
Future<void> handleAutoRenewal() async {
    final settings = await _settingsRepository.getSettings();
    if (!settings.isPrayerNotificationsEnabled) {
        debugPrint('⏸️ Auto-renewal skipped — prayer notifications disabled');
        return;
    }
    // ... proceed to reschedule
}
```

### `onLocationChanged()` guard
```dart
// BEFORE: if (!settings.isPrayerEnabled) return;
// AFTER:  if (!settings.isPrayerNotificationsEnabled) return;
```

### `togglePrayerReminders` guard
```dart
// BEFORE: if (currentSettings.isPrayerEnabled) { scheduleSevenDays(); }
// AFTER:  if (currentSettings.isPrayerNotificationsEnabled) { scheduleSevenDays(); }
```

## 5. Settings UI Behavior

```
── Prayer & Worship ──────────────────────────────────────
[mosque]        Prayer Times Card        [toggle: isPrayerEnabled, default OFF]
[notification]  Prayer Notifications     [toggle: isPrayerNotificationsEnabled, default OFF]
  ↳ if notifications ON:
    [alarm]     Prayer Reminder (15 min) [toggle: enablePrayerReminders, default ON]
  ↳ if card OR notifications ON:
    [location]  Prayer Times Location    [nav tile]
[book]          Morning/Evening Athkar   [toggle: isAthkarEnabled]
```

**Decision: notification toggle is always visible, regardless of card state.**
Rationale: A user can receive athan alerts without wanting the prayer card on the dashboard. Independent toggles match the product intent.

**Decision: location nav shown when either feature is on.**
Rationale: Both card and notifications need a location to calculate prayer times.

**`?? true` flicker fix:**
- `settings?.isPrayerEnabled ?? true` → `settings?.isPrayerEnabled ?? false` ✅
- `settings?.isPrayerNotificationsEnabled ?? false` ✅ (new toggle, correct default)
- `settings?.enablePrayerReminders ?? true` ✅ (sub-setting, `true` default is correct here)

## 8. Remaining Risks

- **Isar existing users**: `isPrayerNotificationsEnabled` reads `false` from Isar default on first access for existing records. On app startup `initializeScheduling()` will see `false` and call `disableNotifications()` — this cancels any previously scheduled prayer notifications for users who had them. This is the correct behavior (they were scheduled under the old ambiguous toggle; the new explicit field is opt-in). **Risk**: existing users may notice prayer notifications stop until they explicitly re-enable in Settings. This should be communicated via onboarding or a migration dialog if needed.
- **`smart_prayer_wrapper.dart` unchanged**: Still reads `isPrayerEnabled` for card visibility — correct.
- **`prayer_conflict_service.dart` unchanged**: Still reads `isPrayerEnabled` for conflict checking — correct (conflict check is a feature-gate for the card/workflow, not for notifications).
