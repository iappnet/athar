## 5. Confirmed Root Cause

**Device test symptom:** Save button turns grey → loading spinner runs forever → no task added → sheet does not close → no error shown.

**Root cause:** `TaskCubit.addTask()` at line 314 calls:
```dart
await getIt<SubscriptionCubit>().ready;
```

`SubscriptionCubit` was annotated `@injectable` (GetIt factory). Each `getIt<SubscriptionCubit>()` call creates a **new** instance. The new instance's `_readyCompleter` is initialized in the constructor and only completed when `loadStatus()` is called on **that specific instance**. `loadStatus()` is called at app startup on instance A (via `app.dart`), but `addTask()` creates instance B — whose `_readyCompleter` never completes → `await ready` hangs forever.

The prior session's state-check fix was correct but unreachable — `addTask()` never returned because it was stuck on this `await`.

## 6. Old Behavior

```
User taps Save
  → _handleSave() called
  → await taskCubit.addTask(...)
      → addTask() calls: await getIt<SubscriptionCubit>().ready
          → getIt() creates NEW SubscriptionCubit instance (factory)
          → _readyCompleter on new instance is never completed
          → await hangs FOREVER
  → _handleSave() never returns
  → _isSaving stays true → button grey → spinner runs forever
  → Sheet never closes → No error shown
```

---

## 7. New Behavior

```
User taps Save
  → _handleSave() called
  → await taskCubit.addTask(...)
      → addTask() calls: await getIt<SubscriptionCubit>().ready
          → getIt() returns SAME singleton instance (lazySingleton)
          → _readyCompleter already completed at startup (loadStatus() ran on same instance)
          → await resolves immediately
      → limit check, repository write, emit TaskAdded
      → addTask() returns
  → state check (TaskError/TaskFreeLimitReached → sheet stays open)
  → else → navigator.pop() → sheet closes
```

## 13. Risks

| Risk | Severity |
|---|---|
| `SubscriptionCubit` as lazySingleton — lifecycle on logout/re-login | Low — `_readyCompleter` is a one-shot; if user logs out and back in, new `loadStatus()` call on same instance is safe (idempotent guard: `if (!_readyCompleter.isCompleted)`) |
