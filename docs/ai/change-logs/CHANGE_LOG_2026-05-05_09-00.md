## 5. Confirmed Root Cause

`_handleSave()` called `navigator.pop()` unconditionally after `await taskCubit.addTask(...)`.

`addTask()` swallows all errors in two ways:
1. **Repository exception** — `try/catch` in `addTask()` emits `TaskError`, returns normally
2. **Free limit reached** — emits `TaskFreeLimitReached`, returns normally

In both cases `addTask()` returns without re-throwing. `_handleSave()` sees a clean return and closes the sheet. Result: user's form data is lost and the save failure is only visible in `task_page.dart`'s BlocListener (which fires but is behind the now-closed sheet).

---

## 6. Old Behavior

```
User taps Save
  → validation passes
  → await taskCubit.addTask(...)
      [internally: catches exception, emits TaskError, returns]
          OR
      [internally: hits limit, emits TaskFreeLimitReached, returns]
  → addTask() returns normally (no exception thrown)
  → if (mounted) navigator.pop()   ← ALWAYS EXECUTED
  → Sheet closes
  → User's form data LOST
  → Error feedback only via task_page.dart BlocListener (confusing timing)
```

---

## 7. New Behavior

```
User taps Save
  → validation passes
  → await taskCubit.addTask(...)
  → if (!mounted) return
  → final postSaveState = taskCubit.state
  → if (postSaveState is TaskFreeLimitReached || postSaveState is TaskError)
      → setState(() => _isSaving = false)   // reset spinner
      → return                              // sheet STAYS OPEN
      → task_page.dart BlocListener shows snackbar/upgrade dialog on top
  → else (save succeeded)
      → if (mounted) navigator.pop()        // sheet closes only on success
```
