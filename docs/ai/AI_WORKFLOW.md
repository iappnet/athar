# AI Workflow — Rules for Claude Code on Athar

## EXECUTION RULES (MANDATORY)

1. `FEATURE_INDEX.md` → select ONE feature → select ONE entry file → execute.
2. First valid file match = locked. No re-search. No alternative exploration.
3. Max 2 searches · max 2 reads. Cap reached → stop, assume correctness, execute.
4. Over-validation is forbidden. 70% confidence = go.
5. One file solves it? Read only that file.

---

## Step 1: Check docs/ai/ before touching code

Use this funnel. Exit at the first step that answers your question — do NOT check all four.

1. `KNOWN_PROBLEMS.md` — known bug with a listed target file? Go directly to that file. **Stop.**
2. `FEATURE_INDEX.md` — find the MANDATORY START FILE. Once found: your next action is Read or Edit on that file. **Stop.**
3. `DATA_FLOW_INDEX.md` — only if flow tracing is needed beyond the MANDATORY START FILE.
4. `STATE_MANAGEMENT_INDEX.md` — only for cubit instance disambiguation.

After step 2 gives you a file name: Read or Edit it. Do not continue checking other docs.

## Step 2: SocratiCode for unknown territory

If docs/ai/ doesn't cover the area, use SocratiCode to search before reading files:

```
codebase_search("exact symbol or concept")  → find files
codebase_graph_query("relative/file/path")  → see imports/dependents
```

Do NOT speculatively open files to "see what's in them". Search first.
First result = accepted. Do NOT search for better alternatives.

## Step 3: Minimal targeted reads

Read only the specific lines SocratiCode or docs/ai/ point to. Never `cat` an entire file to find a function — use `grep` or line-ranged reads.

## Step 4: Understand the BlocProvider tree before touching cubits

Any cubit-related change requires knowing which instance is active at the relevant context. Three TaskCubit instances exist (global, MainPage, UnifiedTasksPage). Wrong one → silent no-op.

See `STATE_MANAGEMENT_INDEX.md` for the full tree.

## Step 5: After any change

1. Run `flutter analyze` — must be clean
2. For widget changes: build the affected extension (`AtharTaskWidgetExtension`, `AtharHabitWidgetExtension`, or `AtharPrayerWidgetExtension`)
3. Update `docs/ai/KNOWN_PROBLEMS.md` if you fixed or discovered a bug
4. Update `docs/progress/` phase files if this is part of a tracked phase

## Non-Negotiable Rules

### Never rename WidgetKeys constants
`lib/core/services/widget_data_service.dart` — constants map directly to UserDefaults keys on installed devices. Rename = silent data loss for all users.

### Never edit *.g.dart files
Generated by `isar_generator`. Changes are overwritten on next `build_runner` run.

### Never add page-level FABs to TaskPage or HabitPage
The central NavBar `+` button is the only add entry point. Duplicate FABs are a product decision reversal.

### Never change App Group ID
`group.com.iappsnet.athar` — changing this breaks widget data on all installed devices.

### Do not use GoRouter
`core/config/routes.dart` is an unused stub. All navigation uses named routes in `app.dart`.

## Adding a New Feature

1. Create `lib/features/<name>/` with the full `data/domain/presentation` tree
2. Add `@lazySingleton` to the repository impl
3. Run `build_runner` to register it in DI
4. Create the cubit; register it in `app.dart` MultiBlocProvider if global
5. If it needs widget data: add new versioned keys to `WidgetKeys`, write to `WidgetDataService`, increment `widgetDataVersion`

## Adding a New WidgetKey

1. Add constant to `WidgetKeys` abstract class (new name, new UserDefaults key string)
2. Increment `widgetDataVersion`
3. Write the value in the appropriate `push*Data()` method
4. Read it in the corresponding Swift widget file
5. Document in `docs/ai/WIDGET_INDEX.md`

## Fixing a Widget Bug

1. Start with `docs/ai/WIDGET_INDEX.md` — check the known issues section
2. Check `docs/ai/KNOWN_PROBLEMS.md`
3. Decide if the bug is in Flutter (data push side) or Swift (display/interaction side)
4. Flutter-side: check `WidgetDataService`, then the relevant cubit's `push*Data` call site
5. Swift-side: check the relevant `Athar*Widget.swift` file; verify `readEntry()` reads the correct key

## Changing Language/Locale Behavior

1. `LocaleCubit` (`lib/core/presentation/cubit/locale_cubit.dart`) — runtime switching
2. `MaterialApp.localeResolutionCallback` in `app.dart` — locale-to-supported-locale mapping
3. `lib/l10n/app_ar.arb` + `app_en.arb` — string content; run `flutter gen-l10n` after edits
4. Widget locale: `athar_app_locale` in UserDefaults; `WidgetDataService._readLocale()` reads from `FlutterSecureStorage`
